# 三条基础清洗规则 v1

原则（来自功能清单）：**有把握的自动应用，没把握的标黄等你确认；看不懂的不丢。**

每条规则的结论写进 sidecar 的 `decisions`，带 `status`（auto / review）、`evidence`（数字）和 `reason`（一句话）。用户确认或否决后变成 `confirmed` / `rejected`，以后重新分析也不会被覆盖。

全部比较都用整数（比例写成交叉相乘），C++ 照抄就能逐位复现。阈值集中在各规则文件顶部。

> **阈值现在是对着合成样例定的，还没见过真实工程。** 拿你自己的 FL 导出跑过一批之后，这些数大概率要调。

音高一律用 MIDI 号（60 = 中央 C）。注意 pianoroll-core 的 `pitchName(p, 5)` 把 60 叫 C5，所以下文的 “C0（MIDI 12）” 在画布上会显示成 C1。

## 运行顺序

1. **按通道拆轨** → 决定初始声部映射（只在第一次分析或 `--reset` 时建映射）
2. **认乐器**：轨名关键词 → 音色号（0 不算）→ 第 10 通道当鼓。拆开的声部先看音色号再看轨名（type 0 文件的轨名往往是曲名）
3. 对每个 stream：**keyswitch → 八度 → keyswitch → …**，转到八度结论不变为止，最多 3 圈。
   keyswitch 要知道乐器音域（八度修正后的），八度判断要先去掉 keyswitch，两者互相喂

## 规则一：按通道拆轨（`channelSplit`）

一个 MTrk 块里有 ≥ 2 个通道带音符时出一条结论：

| 条件 | 结论 |
|---|---|
| type 0 文件 | auto：拆 |
| 各通道“音色身份”两两不同（program 不同，或一个是第 10 通道） | auto：拆 |
| 有两个通道音色相同，或有通道没设音色 | review：先合成一条声部，所有音符标黄 |

review 的理由：同一个乐器故意分通道（比如采样器按通道放不同演奏法）时，应该合起来看。确认后（`decide … confirm`）才拆成每通道一条。

## 规则二：识别 keyswitch（`keySwitch`）

对每个 stream 的低端和高端各做一次（高端把音高镜像后用同一套逻辑）。鼓通道跳过，音符少于 4 个跳过。

**找候选簇**

- 按空档找：从低到高看相邻的两个不同音高，取空档最大的那个位置，把它下面的音高当候选。候选最多 12 个不同音高、音符数不到这一路的一半，空档 ≥ 5 个半音
- 找不到、但乐器已知：把低于乐器演奏下限（换算到原始音高 = 下限 − 八度修正）的音高当候选。空档 ≥ 2，音符数 ≤ 25%（再多就更像整体八度错位，交给规则三）

**证据**

| 名字 | 含义 |
|---|---|
| `extreme` | 候选全 ≤ 23（B0）；高端全 ≥ 108（C8） |
| `outsideInstrument` | 乐器已知，候选全在演奏极限之外 |
| `gap` | 候选和正常音之间的空档（半音） |
| `lead` | 候选音按下后 4 拍内（或提前不超过 1/8 拍）有正常音起音的个数 |
| `doubled` | 和正常音构成八度叠加的个数：同音名，起音差 ≤ 1/8 拍，收音差 ≤ max(1/8 拍, 较长音长的 1/4) |
| `inline` | “接在旋律线上”的个数：起音时恰好有前一个音结束、收音时恰好有下一个音起（都是 ±1/8 拍），而起音时没有正常音一起起——正好填满旋律里的一个空位 |

**先排除**（不在极端音区时）：候选不到 3 个音；或者乐器已知、候选都在它能演奏的音域里、空档又不到 12 个半音。
这两条来自第一个真实工程（liubian-full-v3）里的 4 个误报：钢琴左手 2 个 A1、钢片琴 3 个旋律音、小提琴 1 个高音、Pad 2 个低音。

**判定**（n = 候选音符数；“乐器可信” = 来源是 user / name / drumChannel）

- **auto**：位置够硬（`extreme`，或 `outsideInstrument` 且乐器可信）
  且空档 ≥ 7（`outsideInstrument` 且乐器可信时不要求）
  且 lead ≥ 60%、doubled ≤ 20%、inline ≤ 20%
- **review**：（空档 ≥ 7 或 `outsideInstrument` 或 `extreme`）且 lead ≥ 50%、doubled ≤ 50%、inline ≤ 50%
- 其余不报

**各证据防的是什么**

- `doubled` 防钢琴：A0 + A1 的低音八度位置极端、空档也大，但每个都和 A1 叠在一起
- `inline` 防写过了音域的旋律音：它们出现在旋律的位置上，前一个音一结束就起
- `lead` 防孤零零的低音：keyswitch 总是为后面的音服务

**投影**：auto / confirmed 的音标 `noteFlagKeySwitch`（画布默认不画），不参与音域判断，不跟着八度平移。review 的音照常显示并标黄。

## 规则三：找音源八度偏移（`octaveShift`）

原因：各音源对“中央 C 在哪个八度”约定不同，或某些音源按记谱音高接收（短笛、低音提琴、吉他），导出来的音整体差一两个八度。

需要乐器已知且有音域（鼓不做），去掉 keyswitch 后至少 8 个音。

把正常音整体平移 −24 / −12 / 0 / +12 / +24，对每个平移量数超出演奏极限的音（hard）和超出舒适音域的音（soft）。按 (hard 少, |平移| 小, soft 少) 选最好的平移量。

- 不报：最好的就是 0
- **review**：原位 hard ≥ 10% 且 ≥ 2 个；平移后 hard ≤ 5%；平移后 soft 比原位少
- **auto**：在 review 的基础上，乐器可信，原位 hard ≥ 20%，平移后 hard = 0，平移后 soft ≤ 原位的一半

auto 门槛定得高，是因为只有少数几个音出界说明不了整条音源错了八度。用 30 条随机声部压测时，旧门槛把一条只有 11% 的音出界的圆号自动降了八度，见样例 `octave_few_outliers`。

**投影**：auto / confirmed 的平移加到非 keyswitch 音上。review 时不平移，原位超极限的音标黄。

## 已知局限

- 只能抓到“出界”的八度错位。一条大提琴整体高一个八度、却刚好全落在大提琴音域里（比如 55–82），这条规则看不出来，只能手动改。以后可以考虑加“音区重心”这类特征
- keyswitch 只认“音高聚成一小簇、和正常音分得开”的。用 CC 或 program change 切演奏法的音源不在这条规则里
- 乐器库的音域是通行范围的粗略取值，没逐条核对过某一本教材
- 轨名关键词表是凭常见写法拍的，偏英文 / 意大利文 / 德文缩写，中文名只覆盖了标准译名。你的 FL 工程的命名习惯，第一批真实样例一跑就知道缺什么
